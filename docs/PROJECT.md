# Паспорт учебного проекта

## 1. Общая информация

| Поле | Значение |
| --- | --- |
| Название | Между Булок |
| Тип | Учебный frontend-проект |
| Формат | Одностраничный адаптивный сайт |
| Предметная область | Концепция стритфуд-кафе |
| Язык интерфейса | Русский |
| Платформа публикации | GitHub Pages |
| Основные технологии | HTML5, CSS3, Vanilla JavaScript |

## 2. Цель проекта

Разработать интерактивный промосайт вымышленного кафе, закрепив навыки создания пользовательских интерфейсов средствами нативных веб-технологий.

## 3. Задачи

1. Спроектировать структуру одностраничного сайта.
2. Создать визуальную концепцию и единую типографическую систему.
3. Реализовать адаптивное отображение на мобильных и настольных устройствах.
4. Добавить навигацию по разделам и анимации прокрутки.
5. Реализовать демонстрационное меню с категориями и выбором соусов.
6. Создать клиентскую корзину с подсчётом количества и стоимости.
7. Реализовать демонстрационный сценарий оформления заказа с проверкой формы.
8. Добавить интерактивный выбор места в зале и блок часто задаваемых вопросов.
9. Опубликовать результат с помощью GitHub Pages.

## 4. Структура пользовательского интерфейса

- **Главная:** название, фирменная иллюстрация и короткое представление концепции.
- **Концепция:** описание идеи и атмосферы заведения.
- **Как это работает:** демонстрация последовательности выбора блюда.
- **Меню:** категории, позиции, цены и добавление в корзину.
- **Соусы:** переключение вариантов и добавление выбранного соуса.
- **Пространство:** описание условного зала и выбор места.
- **FAQ:** ответы на типовые вопросы.
- **Контакты:** демонстрационные адресные сведения и финальный экран.

## 5. Логика работы

### Меню и корзина

Пользователь выбирает категорию, добавляет позиции и меняет их количество. Состояние корзины сохраняется в Local Storage браузера. Данные не передаются на сервер.

### Выбор места

Пользователь может выбрать одно из условных мест. Выбор используется только в демонстрационном интерфейсе.

### Форма заказа

Форма проверяет обязательные поля на стороне клиента и показывает завершающий экран. Реальной отправки заказа, SMS или уведомления заведению нет.

## 6. Техническая реализация

Вся реализация находится в `index.html`:

- HTML отвечает за структуру и семантику.
- CSS отвечает за дизайн, адаптивность, состояния и анимации.
- JavaScript управляет меню, корзиной, формой, навигацией и интерактивными элементами.
- Local Storage используется для локального состояния корзины.

Сторонние библиотеки и сборка проекта не требуются. Для загрузки веб-шрифтов при наличии сети используется Google Fonts.

## 7. Ограничения и дальнейшее развитие

Текущая версия является демонстрационным прототипом. Для превращения её в реальный сервис потребуются серверная часть, API, база данных, безопасная обработка персональных данных, система управления меню и интеграция заказов.

Возможные направления развития:

- вынести CSS и JavaScript в отдельные файлы;
- добавить автоматические проверки доступности и адаптивности;
- подключить серверное API для заказов;
- реализовать административное управление меню;
- добавить тесты клиентской логики.

## 8. Критерии результата

- Страница открывается без сборки и установки зависимостей.
- Основные разделы доступны через навигацию.
- Меню, корзина и выбор места реагируют на действия пользователя.
- Интерфейс адаптируется к мобильной ширине.
- Демо-сценарии не создают впечатления реальной отправки заказа.
- Сайт доступен через GitHub Pages.

## 9. Примечание

Название, фирменная концепция, меню, адрес и прочие сведения используются в рамках учебной демонстрации. Проект не представляет реальное заведение и не должен использоваться для принятия реальных заказов.
